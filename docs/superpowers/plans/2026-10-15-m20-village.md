# M20 — Village Ambience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Foley makes a Minecraft village audible as a place: a bell that rings more often in a storm (and never replaces the game's), the low murmur of voices and animals panned to the bell block (one shared bed per village, regardless of how many villagers live there), the smith's anvil (a high-Q metal ring) and hammer taps, and scattered animals (chickens at coops, cows by fences) placed at structures.

**Architecture:** Four sub-features join under one new client-tick entry — `VillageAmbience` — that scans the area for the village bell (the anchor, a `bell_block` tile entity in Java), the smith's workstation (`blast_furnace` within the village), and the village's animal structures (`coops` and `fences` near villagers). The bell uses a brand-new `FOLEY_SHOT_BELL = 17` one-shot (high-Q bowl ring at ~440 Hz); the murmur is a new *per-village bed* of pre-rendered voice calls and animal one-shots that loops seamlessly at low volume, gated by `FoleyClient.oneShot()` and capped to one stream per village so a city of many villages stays within the 8-stream budget; the smith uses M4's existing `FOLEY_CONTACT_TAP` on metal; the scattered animals reuse existing primitive birds/frog calls placed at sampled structure positions. One new toggle `village` joins the existing 19 (`sculk` between `boolean sculk` and `long voices`); no other field is reordered, no other files modified.

**Tech Stack:** Rust (foley-synth, foley-ffi, foley-dsp), Java 21 (mod), Fabric 1.21.x, cbindgen (`cargo xtask header`). No new bed kind, no new primitive, no new SoundModel record.

**Spec:** This is M20, a milestone added in this plan. The spec the plan argues from is the prompt's M20 description and the orchestrator's global constraints ("bells ring more in storms", "murmur panned to the bell", "audible within 50 m", "one shared sound per village", "anvil ring + hammer ticks", "scattered animals at structures"). The actual `docs/PLAN.md` does not yet have an M20 section; this plan is its first draft.

**Interfaces:**

```rust
/// A village bell's ring: a high-Q bowl ring at ~440 Hz, with two
/// inharmonic overtones for the bell's "shimmer". `q` (0.5 to 20) controls
/// how long it rings. `seed` mixes a small phase offset so each bell has
/// its own distinct ring.
pub fn bell(q: f32, seed: u64) -> Vec<f32>;
```

The bell is `Bubble`-style: a damped sinusoid at ~440 Hz (the bell's strike tone), with an overtone at 1.18× for the "strike", and a smaller one at 1.49× for the "hum". `q=8` rings for ~2 s. The bell is louder and brighter than the sculk ring, but uses the same shape: amplitude decays exponentially at `τ = 0.5 / q` seconds.

- [ ] **Step 1: Write failing tests in `crates/foley-synth/src/bell.rs`**

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::SAMPLE_RATE;

    fn rms(s: &[f32]) -> f32 {
        (s.iter().map(|x| x * x).sum::<f32>() / s.len().max(1) as f32).sqrt()
    }

    fn pitch(s: &[f32]) -> f32 {
        // Zero-crossing rate on the loudest 10 ms window.
        let loudest = s
            .iter()
            .enumerate()
            .fold((0usize, 0f32), |m, (i, x)| if x.abs() > m.1 { (i, x.abs()) } else { m })
            .0;
        let w_start = loudest.saturating_sub(240);
        let w_end = (loudest + 480).min(s.len());
        let w = &s[w_start..w_end];
        let crossings = w.windows(2).filter(|x| x[0] <= 0.0 && x[1] > 0.0).count() as f32;
        crossings * SAMPLE_RATE as f32 / w.len() as f32
    }

    #[test]
    fn bell_is_a_higher_damped_tone_than_sculk() {
        let out = bell(8.0, 1);
        let p = pitch(&out);
        // Bell is at ~440 Hz, sculk at ~200. The 440 fundamental must be loud enough to read.
        assert!((350.0..=550.0).contains(&p), "bell pitch {p} Hz");
        assert!(out.iter().all(|x| x.is_finite() && x.abs() <= 2.0));
        assert!(out.len() < 4 * SAMPLE_RATE as usize);
        assert!(rms(&out) > 0.02, "bell too quiet");
    }

    #[test]
    fn higher_q_rings_longer() {
        let low = bell(0.5, 2);
        let high = bell(20.0, 2);
        let half = |v: &[f32]| rms(&v[v.len() / 2..]);
        assert!(half(&high) > 4.0 * half(&low), "high q {} vs low q {}", half(&high), half(&low));
    }

    #[test]
    fn same_seed_is_deterministic() {
        assert_eq!(bell(8.0, 42), bell(8.0, 42));
    }
}
```

## Task 5: `VillageAmbience` controller

**Files:**
- Create: `mod/src/main/java/io/github/cumsauce/foley/audio/VillageAmbience.java`
- Create: `mod/src/main/java/io/github/cumsauce/foley/audio/VillageBed.java`

**Interfaces:**

```java
public final class VillageAmbience {
    /** Per-tick scan cadence (10 ticks = 0.5 s). */
    private static final int SAMPLE_EVERY = 10;
    /** How far the scan looks for bell, smith and animals (blocks). */
    private static final int RADIUS = 64;
    /** Village murmur audible within this many blocks of a bell block. */
    private static final int MURMUR_RADIUS = 50;
    /** Max simultaneous village murmur beds (matches FoleyBeds.MOST). */
    private static final int MAX_BEDS = 2;

    public VillageAmbience(NativeBridge bridge);
    public void tick(Minecraft minecraft);
    /** The M20 sounds Foley has played this session. For the gametest. */
    public int played();
    public VillageBed beds();
}
```

The tick:
1. **Scan for bell blocks** within `RADIUS`. For each bell block, ring it once per `30..60 s` (randomized). The ring is louder the more it rains or thunders (the bell is more often used in a storm). Use `bridge.renderOneShot(SHOT_BELL, q, bellSeed)` to render and play via `Sounds.play(minecraft, "village_bell", ...)` with the bell position.
2. **Murmur bed**: each unique bell block gets ONE murmur — a stream at low volume that loops. Capped at `MAX_BEDS` so a city of many villages stays within the 8-stream budget. The stream is rendered every `SAMPLE_EVERY` ticks as a Poisson mix of low-volume voice calls (`bridge.renderVoice(Mob::Villager, Call::Ambient, seed)`) and low-pass-filtered animal one-shots. The bed is placed at the bell block (`BedSound.place(villagePos)` is the *audio* place, but the murmur is conceptually *at the village centre*, which the bell is the proxy for).
3. **Smith scan**: within `RADIUS`, look for `Blocks.ANVIL` near a `Blocks.BLAST_FURNACE` — a smith's setup. When the player strikes the anvil (right-click; detected via `Minecraft.player.swing`), play `FoleyClient.gain() * 0.4f` of `bridge.renderContact(CONTACT_TAP, METAL, 2.0f, seed)` at the anvil's position, played via `Sounds.play(minecraft, "smith_anvil", ...)` with the anvil position.
4. **Scattered animals**: every `SAMPLE_EVERY` ticks, scan within `RADIUS` for chicken coops (`Blocks.CHEST` with a chicken nearby or `Blocks.HAY_BLOCK` adjacent to chickens; the simpler version is "any chicken within 4 blocks of `Blocks.HAY_BLOCK`") and cows by fences (any cow within 4 blocks of `Blocks.OAK_FENCE`). When found, fire a low-volume pre-rendered bird/animal one-shot at the structure every 3..8 s.

The scan budget: `RADIUS=64` blocks, step 4, means `33² × ~64 = ~70 000` blocks. Pin to under 5 ms by reducing the step in `scanAnimalStructures` if needed. The M21 plan's review-focus note about scan budgets applies here too; the implementer times the scan on first run and adjusts if it exceeds 5 ms.

## Review Focus

These inputs/failure modes are implied by the spec but no test exercises them; they go here once, and the tests that pin them live in the listed task:

- **Per-village murmur cap.** A village is one shared murmur sound. With many villages in view, `VillageBed` could grow without bound. Pin in Task 5 by adding an assertion in `VillageBed` that the map size never exceeds `MAX_BEDS`. The test pins: spawning 5 bells within `RADIUS` and asserting `FoleyClient.villageAmbience().beds().size() <= MAX_BEDS`.
- **Bell ringing in a storm.** The spec says the bell rings more often in a storm. Pin in Task 5 by asserting `VillageAmbience`'s scan timer scales inversely with the storm rating (`minecraft.level.getRainLevel(1f) + minecraft.level.getThunderLevel(1f)`).
- **Bell is layered, not replaced.** The spec says Foley doesn't replace the game's bell, it layers. M20 must NOT add a `Set<Identifier>` arm to `Replacements.replace` for `SoundEvents.BELL_*`. Pin by running the existing gametest's M20 bell step and asserting `FoleyClient.replaced()` *does not* increment for `BELL_USE` — the game's own plays.
- **Toggle round-trip.** A config with `village = false` should round-trip through `FoleyConfig.fromJson(...).toJson()`. Pin in Task 4 by extending `FoleyConfigTest.itRoundTrips` to use `village=false`.
- **Scan budget.** The four scans (`RADIUS=64`) sample ~70 000 blocks. Pin in Task 5 by timing `VillageAmbience.tick` on a typical client and asserting under 5 ms for the scan itself. The implementer adds `assertTrue(scanTimeNs < 5_000_000)` to `VillageAmbienceTest` after measuring. If it exceeds, the implementer drops the step in `scanAnimalStructures` from 2 to 4.
- **One-shot gate.** The bell ring consumes the per-tick one-shot budget (`FoleyClient.oneShot()`), which is shared with the M21 one-shots. Pin in Task 5 by asserting `FoleyClient.oneShot()` is checked before playing the bell.
